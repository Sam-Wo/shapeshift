## Flags

1. **Broad Drug Repurposing Hub: non-commercial, possibly no-redistribution (affects names, MoA, targets, clinical phase).** This is the most serious flag.
   - Every Hub file we hold says `The Drug Repurposing Hub data is provided for non-commercial use only.` That covers the 20200324 files and the 2017/2018 files in `cellcheck/data/lincs/`.
   - The Hub page FAQ says the data "may not be repackaged or redistributed for commercial purposes without permission".
   - The license URL the Hub page attaches to every download (`https://clue.io/terms`) is stricter. It says "You agree to not redistribute ... Data Files" and "restricted to academic use within not-for-profit institutions", and it asks you to contact Broad before distributing a significantly different derivative work. Those terms are written around registered CLUE access keys, so whether they bind the public Hub flat files is **unclear**. Taken at face value, though, they forbid redistributing the files and require permission for derivatives.
   - The same content reaches us through open-licensed wrappers:
     - the Gallery (CC0), which hosts the raw Hub files (header intact) and the header-stripped `repurposing_hub_annotations_processed.tsv`;
     - JUMP-Target (MIT), whose `pert_iname`/target annotations "were obtained from clue.io/repurposing";
     - lincs-cell-painting (CC0 for "data, results, and figures"), which mirrors the raw Hub files in `metadata/moa/clue/`.
   - **Whether the wrapper's CC0/MIT overrides the Hub's own terms is unclear.** All parties are Broad, but no source says the restriction was lifted. Treat Hub-derived columns as restricted.
   - In this project the Hub-derived fields are:
     - `jump_hub_name` and `jump_hub_moa` (from `overlap.py`, carried into `step2/build_units.py` as `hub_moa`);
     - the Tier 3a name bridge (`Metadata_repurposing_name`), which shows up in `match_via` strings ("name '...' = JUMP/Repurposing Hub name") and in the `name_agrees`/`hub_name_agrees` flags;
     - any `pert_iname`/`moa`/`target` columns taken from the raw Hub files or JUMP-Target.
   - "Non-commercial" alone would not forbid public redistribution. It would still conflict with publishing those columns under a permissive repo license (MIT/CC0/CC BY) that allows commercial reuse. The clue.io terms go further and bar redistribution and non-academic use. We also do not know whether the repo owner or downstream users are commercial. If the project is itself commercial, the Hub terms restrict *use*, not just redistribution.

2. **Tahoe `moa-fine`, `moa-broad`, `targets`: CC0 at the Tahoe level, but upstream provenance is unclear.** The Tahoe README says `moa-fine` is "Derived from MedChemExpress and curated with GPT-based annotations", `targets` "were proposed by GPT-4o based on compound names and then validated against MedChemExpress information", and `moa-broad` was "inferred ... using compound target data and curated descriptions from MedChemExpress". Tahoe licenses the whole dataset CC0. The MedChemExpress terms were not checked, and short factual labels are generally low risk. Rating: **low risk, but formally unclear**. These are the MoA labels this project mainly uses (`step2/build_units.py`, `step2/compare_tiers.py`).

3. **Fold-change-derived Tahoe signatures.** The source (`pseudobulk_differential_expression`) is CC0, so no license restriction applies to derived signatures. Attribution is requested, not required. **No flag on license grounds.**

4. **EU-OPENSCREEN Zenodo profiles are CC BY 4.0, not CC0.** This is the only source here with a *legally binding* attribution condition. Any committed table or vector derived from `Aggregated_Profiles.zip` needs: credit (Schmied, Zenodo doi:10.5281/zenodo.19347244, plus Wolff et al. 2025), a link to CC BY 4.0, and a note that it was modified. CC BY has no ShareAlike, NonCommercial or NoDerivatives term. The same dataset's Gallery copy (cpg0036 images/metadata) is CC0, so the terms depend on which copy you derived from.

5. **`jump-cellpainting/datasets` license ambiguity.** The only license file is BSD-3 (`LICENCE.md`), which is a software license applied to a repo that is mostly metadata. JUMP Hub says all JUMP data is CC0. Both are permissive. The conservative reading: keep the BSD-3 copyright notice when committing rows from `compound.csv.gz` (JCP2022 IDs, InChIKeys).

6. **Missing license text.**
   - `jump-cellpainting/2026_Chandrasekaran_Seal_Submitted`, the code that generates the processed Hub TSV, has no LICENSE. We only consume its output, which is hosted in the Gallery, so this matters only if code from it is copied.
   - The Repurposing Hub has no named open license. Its terms are split across the file header, the Hub FAQ and clue.io/terms (row 6a), and clue.io/terms shows no date.
   - The live repo-hub.broadinstitute.org page failed TLS verification on 2026-11-22. It was read from a 2026-10-13 Wayback snapshot instead.

7. **No CC NonCommercial, NoDerivatives or ShareAlike licenses** were found in any source. The only non-commercial / no-redistribution / derivative-permission conditions are the Hub's custom terms in Flag 1. They work like NC + ND but are not a CC license.

8. **PubChem:** no license restriction from NCBI, with the caveat that depositors may hold rights. Identifier and property lookups (CID, InChIKey) are low risk.

## Recommendation: what the public repo may commit

**Never commit the raw Hub files.** That means `cellcheck/data/lincs/repurposing_*.txt` (5 files) and any downloaded copy of `repurposing_hub_annotations_processed.tsv`. Have a script fetch them instead (`overlap.py` already downloads the processed TSV). The other raw inputs are CC0/MIT/BSD/CC BY, and the `MOA002_*` platemaps come from lincs-cell-painting (CC0), but committing large raw mirrors is unnecessary anyway.

**(a) Summary statistics and figures: safe to commit**, on the condition that the project is non-commercial research. If it is not, the Hub terms restrict using Hub data at all, whatever gets committed.
- Every non-Hub source is CC0, MIT/BSD, or CC BY. Aggregate statistics such as Mantel r, retrieval scores or tier counts do not reproduce Hub data.
- Add a `DATA_SOURCES`/README section with the citations in the table above. Make the EU-OPENSCREEN CC BY 4.0 attribution explicit wherever figures use those profiles.
- If a figure prints Hub MoA names as category labels, that is low risk but technically Hub content. Prefer Tahoe `moa-fine` labels in figures.

**(b) Per-compound identifier table: commit it, decided column by column.**
- Safe: InChIKey, JCP2022 ID (JUMP: CC0/BSD-3), Tahoe drug name, Tahoe `pubchem_cid`, and Tahoe `moa-fine`/`moa-broad`/`targets` (CC0; Flag 2 is low risk). **Use Tahoe `moa-fine` as the MoA label column.**
- Match tier: safe as a tier code (T1/T2/...). **Drop or scrub `match_via`**, because it embeds Hub names. Treat Tier 3a rows (matched via a Hub name) and the `name_agrees`/`hub_name_agrees` flags as **unclear, low risk**: they record a fact about a Hub name match, not the Hub annotation itself.
- BRD ID: safe if taken from the Gallery, CPJUMP1 or LINCS metadata (CC0) or JUMP-Target (MIT, keep the notice). Unclear if taken *only* from the raw Hub `repurposing_samples` file, but a bare identifier is low risk.
- **Hub-derived columns** (`jump_hub_name`, `jump_hub_moa`, Hub targets, clinical phase, indication): **do not commit them.** Let users regenerate them locally with the provided script.
  - A separate non-commercial-notice file is *not* a safe alternative. clue.io/terms (the license the Hub page links) says "do not redistribute" and asks you to contact Broad before distributing a derivative. Whether those terms apply to the public Hub files is unclear.
  - If Hub columns must be shipped, get written permission from repurposing@broadinstitute.org first.
- Include the BSD-3 notice from `jump-cellpainting/datasets` (and the MIT notice if JUMP-Target columns are used) in a `NOTICE` or `THIRD_PARTY_LICENSES` file.

**(c) Per-compound signature/profile vectors.**
- **Tahoe fold-change signatures:** allowed (CC0); cite Zhang et al. 2025.
- **JUMP (cpg0016), CPJUMP1 (cpg0000), LINCS (cpg0004) morphological profiles:** allowed (CC0); cite the per-dataset paper + Weisbart 2024 + the AWS RODA acknowledgement.
- **EU-OPENSCREEN vectors from the Zenodo profiles:** allowed under CC BY 4.0, *with* attribution, a license link and a modification notice in the file or adjacent README. If they come from the Gallery cpg0036 copy instead, CC0 applies.
- Keep these vectors keyed by InChIKey/JCP2022/Tahoe name only. Do not join in the Hub MoA/name columns, for the reason given in (b).
- Size and practicality: large matrices are better hosted on Zenodo or HF with the same notices, but that choice is not a license constraint.
